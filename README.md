# control. — decide what gets your attention on LinkedIn

A Chrome (MV3) extension that cleans up the LinkedIn home feed. It hides promoted posts, "Jane likes this" network
activity, keyword matches, and anything you describe in your own words ("no humblebrags, only bioinformatics").
Each hidden post collapses to a one-line bar, **"control. hid a post · reason [Show anyway]"**, so you can always
reveal it.

Built for a hackathon, **Track 4: AI-Powered Consumer Products for 1 Billion People**, which is judged on
**innovation, scale and real-world application**. The product is ambient: there is no new app to open, and the feed
you already scroll just gets better.

> Status: working extension on `main` (rules + Claude / Chrome built-in AI filter). Branch
> `feat/on-device-bert-gemma` is moving the AI filter fully on-device (BERT-family model via Transformers.js, with
> Gemma as the fallback for uncertain posts). See [Architecture](#architecture).

## What's built so far (`main`)

| Feature | Where | Notes |
|---|---|---|
| **1. Hide by post type**: promoted, network activity ("X likes this"), suggested | `shared/rules.js` | Regex on the post's header line. Instant, no AI. |
| **2. Hide by keyword** | `shared/rules.js` | Word-boundary match, plural-tolerant, `intern*` wildcards, phrases. |
| **3. "Describe what you want"** AI filter | `background/`, `shared/prompt.js` | Free-text instructions → model returns `show`/`hide` + an 8-word reason per post. |
| **4. Home page layout**: blank home, hide sidebars | `content/content.js`, `content.css` | Unhook-style. |
| Hidden-post bar with **Show anyway** | `content/content.js` (`setBar`) | Optional blur while a post is being checked. |
| Popup + options UI, verdict cache, error reporting | `popup/`, `options/`, `background/` | |

**How a post flows today:** `content.js` extracts the post, then `rules.evaluateRules()` runs. If a rule
matches, the post is hidden and nothing else runs. Otherwise it looks for a cached verdict keyed by
(hash of provider + model + instructions) + post URN. On a miss, it sends `control:classify` to the background, which
**batches 8 posts** (350 ms window, 2 batches in flight) into one model call, caches the answers (up to 3,000,
persisted in `storage.local`), and replies. Any error **fails open**: the post is shown and the error appears in the
popup.

Providers on `main`: **Claude** (user's own API key, default `claude-opus-5-5`) or **Chrome built-in AI** (Gemini
Nano through the Prompt API, run in `offscreen/` because service workers can't reach it).

## Why we're changing it

- **Cost at scale:** a Claude call per 8 new posts is about 50k tokens per user per day. At 1B users that's
  impossible, and "bring your own API key" excludes normal people.
- **Reach:** Gemini Nano needs desktop Chrome, a strong GPU or 16 GB RAM, about 22 GB of free disk, and a
  multi-GB download that Chrome manages. Most of the world's devices can't run it, and we can't bundle it (its
  weights aren't redistributable).

## Architecture

```
post ─▶ 1. rules (regex)          instant, free                   ─▶ hide / continue
     ─▶ 2. verdict cache          per (config, post URN)          ─▶ reuse
     ─▶ 3. BERT-family encoder    on-device, ~10–50 ms/post       ─▶ confident? decide
            (Transformers.js, in the offscreen document)
     ─▶ 4. Gemma (bundled)        on-device, only uncertain posts ─▶ decide
     ─▶ 5. Claude (optional)      only if the user adds a key     ─▶ decide
     ─▶ fail open: show
```

- **Step 3, how it works:** your instructions are parsed into *hide topics* and *show topics* (e.g. "hide
  crypto, only ML research"). Each topic is embedded once. Each post is embedded and compared with them. A big
  margin means decide now; a small margin means the post is **uncertain** and moves on to step 4.
- **Step 4:** Gemma 3 (small instruction-tuned model) reads the post plus your instructions and answers SHOW or
  HIDE. It's an on-device generative LLM, open weights, shipped inside the extension.
- **Reason text** in the bar comes from the topic that matched ("Looks like: crypto") or from the LLM.
- **Model files** are bundled in the extension package at build time (`extension/models/`, gitignored because
  they're too big for git) and loaded with `env.allowRemoteModels = false`, so no data leaves the device.
- **Manifest:** needs `'wasm-unsafe-eval'` in `content_security_policy.extension_pages` for ONNX Runtime WASM.

**Pitch:** an LLM understands what you want, and a tiny on-device model applies it to every post, for free,
privately, in milliseconds.

## Running it

```bash
npm install
npm run vendor            # rebuild extension/vendor/*
npm test                  # unit tests
npm run test:e2e          # Playwright e2e (headless Chromium; HEADED=1 to watch)
```

Load `extension/` as an unpacked extension in `chrome://extensions` (Developer mode on).

Known gaps: `npm run lint` and `npm run zip` point at `scripts/check-manifest.mjs` and `scripts/zip.mjs`, which
don't exist yet.

## Conventions

- No build step for the extension itself. Plain classic scripts hang off `globalThis.control`. Only `vendor/` is
  generated.
- Everything that can fail **fails open** (show the post). An AI problem must never hide content.
- Post text is untrusted data. Prompts tell the model to ignore instructions inside posts.
